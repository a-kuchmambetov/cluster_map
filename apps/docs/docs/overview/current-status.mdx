# Current Status

This page describes the checked-in implementation. Source code and workflow
definitions do not establish production deployment or release acceptance.

## Implementation summary

| Area            | Current state                                                                                                                                                                                                                             |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Web             | Protected map at `/`, GitHub sign-in, and user listing, approval, and deletion at `/admin/users`.                                                                                                                                         |
| API             | Public database health and application readiness checks; authenticated cluster list, layout, occupancy, configuration validation, and SSE endpoints; admin-only user listing, approval by user ID, and deletion under `/api/admin/users`. |
| Public pages    | Privacy Policy at `/privacy` and Terms of Service at `/terms`, linked from the sign-in screen and the global footer. Both name the operator and contact address and show an effective date of 25 September 2026.                          |
| Authentication  | Better Auth sessions, GitHub OAuth, administrator approval, current-role checks, and logout. Email/password sign-in and TOTP two-factor authentication have been removed.                                                                 |
| Database        | Auth and Hive Drizzle schemas, five migrations, PostgreSQL 17 in the full development Compose stack, and an optional static demo seed.                                                                                                    |
| Worker          | One-shot database migration worker with optional administrator promotion of an existing account.                                                                                                                                          |
| Simulator       | Optional demo-only occupancy simulator in `apps/simulator`; disabled unless `SIMULATOR_ENABLED=true` and refused when `NODE_ENV=production`.                                                                                              |
| Live updates    | Shared per-cluster polling with a 30-second delay between completed polls, SSE deltas, and frontend recovery snapshots.                                                                                                                   |
| Shared packages | Auth, admin, common message, and cluster DTOs in `@repo/types`, application errors in `@repo/errors`; `@repo/validators` still contains example validation.                                                                               |
| Tests           | API unit/integration, web Vitest, worker Node tests, simulator Vitest, and deployment change-selection tests; opt-in PostgreSQL auth integration enabled in CI.                                                                           |
| Deployment      | API, web, docs, worker, and simulator Dockerfiles; API/worker/simulator Infisical entrypoints; GitHub Actions image publishing and Coolify webhook deployment.                                                                            |
| Documentation   | Docusaurus site with separate development and build commands; historical contracts under Archive.                                                                                                                                         |

See [Local Development](../getting-started/local-development),
[API Reference](../reference/api), and [Deployment](../operations/deployment).

## Remaining work and limitations

- Hive OAuth and a general profile page are not implemented. GitHub is the only
  sign-in method. Email/password sign-in and TOTP two-factor authentication have
  been removed.
- Connect configuration-validation results to map warnings; the frontend currently
  supplies an empty warnings array.
- Define an age-based stale threshold and measurable performance/accessibility
  acceptance criteria. Current stale behavior responds to failures, not data age.
- Validate production occupancy integration and database privileges. The current
  client is shared by occupancy reads and authentication writes.
- `/api/health/ready` is mounted, but omits layout and sign-in round trips. Deployment workflows do not use it as a gate.
- Verify the operational practices stated in the public privacy/terms pages
  (hosting, providers, retention, same-day deletion, rights requests). The
  Privacy Policy still says email/password sign-in is available, although
  GitHub is the only implemented method.
- The simulation agent is implemented in `apps/simulator` and must be enabled
  explicitly for local/demo databases.
- Existing installations need a coordinated rollout for migration 0004, which
  drops `user.approval_token`; see
  [Approval column removal](../operations/deployment#approval-column-removal).
- Configure environment-specific routing, migration ordering, deployment health
  acceptance, backups, rollback, and TLS/WAF outside the checked-in workflows.
  Vite and web Nginx do not currently proxy `/api`.
- Verify the [Transcendence requirements](./transcendence-requirements) against
  delivered behavior; the points table is a target, not an acceptance result.
