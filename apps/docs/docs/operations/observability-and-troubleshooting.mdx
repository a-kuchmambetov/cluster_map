# Observability and Troubleshooting

## Current signals

`GET /api/health` is public and executes `SELECT 1` with a two-second timeout:

- `200`: `{ "status": "ok", "db": "ok" }`.
- `503`: `{ "status": "degraded", "db": "unreachable" }`.

This tests connectivity, not schema migration state, auth configuration, layout
validity, or occupancy freshness.

`GET /api/health/ready` is also public: it returns `200` with
`{ "status": "ready" }` or `503` with `{ "status": "not-ready" }`. It checks
auth environment variables, exact `WEB_ORIGIN` formatting, HTTPS web/auth URLs
in production, selected schema tables, and Better Auth initialization. Its
database/auth phase has a three-second timeout. It does not query `two_factor`,
validate layout, or test occupancy freshness or an actual sign-in. See the
[readiness reference](../reference/api#get-apihealthready) for its scope.

The request logger records timestamp, method, path, response status, duration in
milliseconds, and an error code when available. Production writes JSON lines to
stdout; other modes use readable console lines. It drops query strings and
redacts approval tokens from `/api/auth/confirm/:id`. It does not log request
bodies, headers, or peer records. Database health failures additionally emit a
`database_health_check_failed` JSON record with phase, elapsed time, timeout,
and sanitized error causes. Production 5xx responses mask internal details;
the error middleware separately writes the error code and message to stderr as
JSON. Readiness failures return only `not-ready` and do not emit a dedicated
diagnostic cause.

The API exposes layout/occupancy mismatch checks through `config-validation`.
SSE reports database poll failures as `DB_UNAVAILABLE`; the frontend preserves
loaded data and retries snapshots. A long-lived stream's request log is not a
per-event signal. Metrics, alerting, and distributed tracing are not configured.

## Troubleshooting

| Symptom                                | Check                                                                                                                              |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| Health returns 503                     | PostgreSQL availability, `PG_*`, and Compose DB health.                                                                            |
| Health works but readiness returns 503 | Auth secret/URL, required GitHub values, exact `WEB_ORIGIN`, HTTPS URLs in production, migrations, and DB permissions.             |
| Health works but login fails           | Auth secret/URL, required GitHub credentials, migrations, password, approval, and any TOTP challenge; health only runs `SELECT 1`. |
| Login returns 403                      | Account approval and trusted origin. New accounts cannot create a session before approval.                                         |
| Admin page/API denied                  | Current user must be both approved and an administrator.                                                                           |
| Browser CORS/auth origin error         | `WEB_ORIGIN`, actual Vite/browser port, `VITE_API_URL`, and cookie credentials.                                                    |
| Map layout fails                       | API working directory, presence of `src/config/clusters.json`, and Zod validity.                                                   |
| Map occupancy is empty                 | Config ID must match DB `cluster.name`; migrate and seed a local demo DB if needed.                                                |
| Map stays stale                        | DB/SSE errors, recovery requests, session validity, and proxy buffering/timeouts.                                                  |
| Timestamp stops advancing              | Unchanged polls produce no delta or freshness timestamp; keepalive comments only check session/connection.                         |
| Browser receives HTML from API calls   | Set `VITE_API_URL` to the API origin or configure external routing; neither Vite nor web Nginx proxies `/api`.                     |
| User deletion returns 500              | Check whether a position references the user's Hive identity; that foreign key blocks deletion.                                    |
| Worker exits with an admin error       | Supply both admin credentials or neither; an existing non-admin/unapproved account cannot be bootstrapped.                         |
| Documentation build fails              | Run `pnpm build:docs` and fix reported MDX/link errors.                                                                            |

For the local database, use `docker compose -f docker-compose.dev.yml ps` and
`docker compose -f docker-compose.dev.yml logs db`. For local applications, use
the same logs command with `api`, `web`, `docs`, `worker`, or `simulator`.
For production, inspect logs and health in the deployment environment.
The worker exits after migration/bootstrap, so a successful exit is expected.
Validate SSE buffering and timeouts in the external proxy; the checked-in web
Nginx configuration only serves static files.

See [Environment Variables](../reference/environment-variables) and [Deployment](./deployment).
