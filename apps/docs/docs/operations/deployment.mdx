# Deployment

Release images are built by GitHub Actions, stored in GHCR, and pulled by Coolify.
API runtime secrets are injected by Infisical at container startup. PostgreSQL is
persistent infrastructure, separate from application releases.

Follow the repository's [manual deployment runbook](https://github.com/a-kuchmambetov/cluster_map/blob/main/manual.md)
for the ordered infrastructure setup, environment gates, migration commands,
promotion and recovery procedures.

## Images and networking

| Application | Dockerfile             | Internal port |
| ----------- | ---------------------- | ------------- |
| API         | `apps/api/Dockerfile`  | 5000          |
| Web         | `apps/web/Dockerfile`  | 80            |
| Docs        | `apps/docs/Dockerfile` | 80            |

Build using the repository root as context. Web requires runtime
`API_UPSTREAM=private-api-hostname:5000`, on a verified private destination network.
It uses same-origin `/api` requests, disables proxy buffering and supports SSE.
The trusted Coolify HTTPS proxy must overwrite forwarded protocol headers.
Docs has no runtime secrets and uses the canonical domain configured in Docusaurus.

API requires Infisical Universal Auth bootstrap credentials plus project and
environment selection. Actual authentication and database values live in `/api`.
Secrets are refreshed only when the process restarts.

## Release sequence

1. CI checks formatting, lint, types, tests, builds, and PostgreSQL integration.
2. Publish builds all three images from trusted branches, with commit tags and digest artifacts.
3. An operator runs the candidate API digest once using `scripts/deploy/migrate.sh`
   with private networking and the environment's `/database` migration identity.
4. The operator approves the GitHub Environment gate after migration succeeds.
5. Deploy updates Coolify digest references, waits for completion and healthy status,
   and checks public availability. API deploys before Web and Docs.
6. Production promotes the exact successful staging artifacts from a main publication.

`/api/health` checks connectivity; `/api/health/ready` also checks authentication
configuration and every declared database column without reading user data.
Authenticated login, cluster/occupancy reads, SSE reconnection and persistence are
manual acceptance checks documented in the runbook.

## Local development and recovery

Root `docker-compose.yml` runs the local database only. Use `pnpm dev` for the
applications; see [Local Development](../getting-started/local-development).
Migrations are explicit; API replicas do not run migrations on startup.

Archive each healthy image digest record. Rollback is an explicit Coolify
redeployment of the last healthy references after checking database compatibility.
Automatic rollback and schema reversal are not implemented. Test database restores
and keep production credentials separate from CI and staging.
