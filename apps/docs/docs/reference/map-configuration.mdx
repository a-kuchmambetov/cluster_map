# Map Configuration

Physical layout is implemented in `apps/api/src/config/clusters.json`. The API
reads `src/config/clusters.json` relative to its working directory each time it
loads configuration. There is no environment override or config cache.

`apps/api/src/features/clusters/clusters.schema.ts` defines Zod validation;
`clusters.service.ts` loads the file and produces layout/validation responses.
The checked-in file defines clusters 1, 2, and 3 with 79, 76, and 32 places.

## File format

This minimal example uses the implemented shape:

```json
{
  "clusters": [
    {
      "id": "c1",
      "number": 1,
      "label": "Cluster 1",
      "rows": [
        {
          "id": "c1r1",
          "number": 1,
          "label": "R1",
          "cells": [
            {
              "kind": "place",
              "id": "c1r1p1",
              "number": 1,
              "position": "bottom"
            },
            { "kind": "gap" },
            { "kind": "place", "id": "c1r1p2", "number": 2 }
          ]
        }
      ]
    }
  ]
}
```

| Field               | Meaning                                                          |
| ------------------- | ---------------------------------------------------------------- |
| Cluster `id`        | Machine key, matched to database `cluster.name`.                 |
| Cluster `number`    | Positive integer used in API URLs.                               |
| Row `number`        | Positive integer, matched to occupancy `row`.                    |
| Cluster/row `label` | Display text.                                                    |
| Row/place `id`      | Identity within the layout; occupancy joins use numbers instead. |
| Place `number`      | Positive integer, matched to occupancy `place` within a row.     |
| Place `position`    | Optional `top` or `bottom` for staggered rendering.              |
| `kind: "gap"`       | Visual spacing; no numbered seat, peer, or occupancy.            |

Layout responses sort rows by descending row number and retain cell order.
An explicit place position wins; otherwise the frontend alternates from the
preceding non-gap place. The first place defaults to `top` if unspecified.
Gaps do not reset alternation. Occupancy and timestamps are separate data.

## Validation

- Cluster IDs and numbers must be unique across the file.
- Row IDs and numbers must be unique within a cluster.
- Place IDs and numbers must be unique within a row, not globally.
- Cluster, row, and place numbers must be positive integers.
- Cells must match the `place` or `gap` variant; positions must be `top`/`bottom`.
- The schema has no version field, minimum array length, or non-empty-string rule.
  Unknown object properties are stripped by Zod rather than rejected.

Unreadable files, invalid JSON, and schema failures produce HTTP 500 via the
error middleware. An unknown requested cluster produces `404 CLUSTER_NOT_FOUND`.

## Occupancy consistency

`GET /api/clusters/:clusterNumber/config-validation` checks occupied database
coordinates against configured `(row, place)` pairs. It returns
`ORPHANED_OCCUPANCY` for unknown coordinates; a mismatch is a `200` response with
`valid: false`, not a structural schema error.

The map currently does not call this endpoint or populate its warnings array.
Unknown occupancy does not add map cells; configured places absent from
occupancy are free. See [API Reference](./api) for response examples.
