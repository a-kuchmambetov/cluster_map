# Environment Variables

API, worker, and DB configuration load the root `.env` via workspace-relative
paths. Vite uses the root as its environment directory. Existing process
variables take precedence over dotenv values.

Development Compose reads `.env` for overrides and provides local auth defaults
when values are missing or empty. It uses `db:5432` inside containers, fixes
`NODE_ENV=development` and `TRUST_PROXY_HOPS=0`, and does not use Infisical.
Unset or empty auth/frontend URLs default to `http://localhost:${API_PORT:-5001}`.
Infisical bootstrap settings below apply to production app Dockerfiles only.

| Variable                                         | Requirement / default                                                                                                    | Consumer                                                                       |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------ |
| `NODE_ENV`                                       | `production` in API/worker release images                                                                                | Error masking, request logs, seed guard                                        |
| `API_PORT`                                       | 5001                                                                                                                     | API listener; Docker health check reads the injected port                      |
| `TRUST_PROXY_HOPS`                               | `0` for direct runs; API image defaults to `1` for Coolify. Match the trusted proxy chain and keep the API port private. | API client IP resolution and auth rate limiting                                |
| `WEB_ORIGIN`                                     | `http://localhost:5173`; set to the actual frontend origin                                                               | API CORS and trusted auth origin                                               |
| `BETTER_AUTH_URL`                                | Required URL; example `http://localhost:5001`                                                                            | Better Auth; worker admin bootstrap                                            |
| `BETTER_AUTH_SECRET`                             | Required, at least 32 characters                                                                                         | Better Auth; worker admin bootstrap                                            |
| `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`       | Non-empty values required by API auth configuration, including password login and seed                                   | GitHub OAuth                                                                   |
| `PG_HOST`                                        | `localhost`                                                                                                              | API, DB tooling, worker                                                        |
| `PG_PORT`                                        | `5432`; also development Compose host port                                                                               | API, DB tooling, worker, Compose                                               |
| `PG_USER`, `PG_PASSWORD`, `PG_DB`                | Each defaults to `app`                                                                                                   | API, DB tooling, worker, Compose                                               |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD`                  | Optional pair; password 8–128 characters; email normalized to lowercase                                                  | Worker initial admin creation                                                  |
| `ADMIN_NAME`                                     | `Administrator`                                                                                                          | Worker initial admin name                                                      |
| `INFISICAL_CLIENT_ID`, `INFISICAL_CLIENT_SECRET` | Required Universal Auth bootstrap credentials in containers                                                              | API and worker entrypoints                                                     |
| `INFISICAL_PROJECT_ID`, `INFISICAL_ENV`          | Required project ID and environment slug in containers                                                                   | API and worker entrypoints                                                     |
| `INFISICAL_DOMAIN`                               | Optional domain selection passed to the installed CLI                                                                    | Infisical CLI                                                                  |
| `INFISICAL_SECRET_PATH`                          | `/api` for API, `/worker` for worker                                                                                     | Infisical runtime secret injection                                             |
| `VITE_API_URL`                                   | Empty by default; use `http://localhost:5001` for direct local access                                                    | Vite frontend; web Docker build argument and GitHub Environment build variable |
| `AUTH_DB_TEST`                                   | `1` enables tests that write to a migrated disposable DB                                                                 | API auth integration suite                                                     |
| `SIMULATOR_ENABLED`                              | `true` enables the live occupancy simulator; defaults to `false` and is disabled in `production`                         | `apps/simulator` local/demo smoke tests                                        |
| `SIMULATOR_USER_COUNT`                           | `20`                                                                                                                     | Number of synthetic identities created by the simulator                        |
| `SIMULATOR_INTERVAL_MS`                          | `5000`                                                                                                                   | Milliseconds between simulator ticks                                           |
| `SIMULATOR_CLAIM_PROBABILITY`                    | `0.7` (must keep total with release probability ≤ 1)                                                                     | Chance an idle identity claims a free seat each tick                           |
| `SIMULATOR_RELEASE_PROBABILITY`                  | `0.3` (must keep total with claim probability ≤ 1)                                                                       | Chance a seated identity releases its seat each tick                           |
| `SIMULATOR_LOCK_KEY`                             | `7269736`                                                                                                                | PostgreSQL advisory lock key used to prevent duplicate simulator instances     |

Worker admin bootstrap requires `BETTER_AUTH_SECRET` and `BETTER_AUTH_URL` when
both admin credentials are set. Empty admin credentials are treated as omitted.
The worker does not require GitHub credentials. API auth does, even when only
password login is used; dummy values are suitable only for local password-only
testing and do not enable GitHub sign-in.

The API readiness endpoint also validates the auth variables, requires
`WEB_ORIGIN` to equal its parsed origin (no path or trailing slash), and requires
HTTPS for `WEB_ORIGIN` and `BETTER_AUTH_URL` in production. A successful database
health probe does not establish that these checks pass.

`PG_PASSWORD_FILE`, a `DATABASE_URL` environment override, `API_UPSTREAM`,
`DOCKER_WEB_ORIGIN`, `WEB_PORT`, and `DOCS_PORT` are not consumed by the current
application/container configuration. The API and web ports are not connected
automatically: configure `VITE_API_URL` or external `/api` routing.

There are no environment settings for the layout file path, SSE poll interval,
frontend recovery interval, or stale-data age threshold. Current polling and
recovery use 30-second constants; stream access checks use 20 seconds.
