# Repository Structure

Cluster Map uses a pnpm workspace. Applications live in `apps/`; shared
TypeScript packages live in `packages/`.

```text
apps/
  api/src/
    config/          # Environment, Better Auth, clusters.json
    features/auth/   # Routes, controllers, services, repository, validation
    features/clusters/ # Map endpoints and shared SSE polling pool
    middleware/      # Auth, request logs, validation, errors
    routes/          # Public database health and application readiness
    scripts/         # Local demo seed
    test/integration/ # API integration suites
    app.ts           # Express setup
    index.ts         # Server startup
  web/src/
    app/             # Route table and providers
    features/admin/  # User listing, approvals, deletion
    features/auth/   # Auth screens, provider, API, and route guard
    features/cluster-map/ # Components, hooks, models, API and SSE client
    components/      # Reusable Untitled UI-based components
    config/          # API base URL
    hooks/           # Shared React hooks
    pages/           # Home, public privacy/terms drafts, and not-found pages
    styles/          # Global styles, theme tokens, typography
    types/           # Vite declarations
    utils/           # Helpers and static data
    main.tsx         # React entry point
  worker/
    src/             # One-shot migrations and initial admin bootstrap
    test/            # Node test-runner suite
  docs/
    docs/            # MDX content and generated sidebar structure
    src/             # Docusaurus components and styles
    static/          # Public assets
packages/
  db/                # Drizzle client, auth/Hive schemas, migrations
  errors/            # Shared AppError
  types/             # Shared auth and cluster-map DTOs
  validators/        # Starter/example Zod validation
.github/workflows/   # PR checks and staging/production image deployments
scripts/deploy/      # Changed-app selection and its tests
```

## Tooling and deployment

The root `package.json` coordinates workspace commands. `pnpm-workspace.yaml`
defines membership; `tsconfig.base.json`, `.oxlintrc.json`, and `.oxfmtrc.json`
configure TypeScript, Oxlint, and Oxfmt.

`.env.example` provides runtime defaults. `docker-compose.dev.yml` runs the
full development stack using `Dockerfile.dev` without Infisical. Each of
`apps/api`, `apps/web`, `apps/docs`, and `apps/worker`
contains its own `Dockerfile`. API and worker have Infisical entrypoints.
`apps/web/nginx.web.conf` serves the frontend without API proxying;
`apps/docs/nginx.docs.conf` serves documentation.

Historical API and DB agreements live under `apps/docs/docs/archive/`; current
behavior is documented in the reference and architecture sections.

## Source ownership

API features colocate routes, controllers, services, repositories, schemas, and
unit tests. Integration tests live under `apps/api/src/test/integration`.
Database models belong in `@repo/db`; DTOs shared between API and web belong in
`@repo/types`. Current auth and cluster Zod schemas are feature-local, not in
`@repo/validators`.

Frontend features own their API calls, state hooks, models, and screens. Shared
visual components live under `components/`, and application providers live under
`app/providers/`. Tests are colocated with the code they exercise.

Generated `dist/`, `build/`, `.docusaurus/`, and `node_modules/` are artifacts,
not source ownership areas.
