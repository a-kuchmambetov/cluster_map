# Domain Model and Data Flow

Shared wire types are defined in `packages/types/src/cluster-map.ts` and
`packages/types/src/auth.ts`. Drizzle schemas live in `packages/db/src/schema/`.

## Domain concepts

| Concept   | Implementation                                                                           |
| --------- | ---------------------------------------------------------------------------------------- |
| Cluster   | Config `{ id, number, label }`; config `id` matches database `cluster.name`.             |
| Row       | Numbered group within a cluster; layout rows are returned in descending number order.    |
| Place     | Numbered cell with an ID and optional `top`/`bottom` position.                           |
| Gap       | `{ kind: "gap" }`, excluded from occupancy and summary counts.                           |
| Occupancy | Database `position.occupied`, holder, and taken time; API exposes only occupied entries. |
| Peer      | Nullable `intraName`, `displayName`, and `photo`; no email in map responses.             |
| Viewer    | Auth user with a session, role (`user` or `admin`), and approval state.                  |

The Hive schema contains `cluster`, `row`, `position`, and `user_hive_info`.
Auth tables are `user`, `session`, `account`, `verification`, and `two_factor`. Database
constraints enforce unique cluster names, row numbers within clusters, and seat
numbers within rows. A position must be either free with no holder/taken time,
or occupied with both fields populated. `user.twoFactorEnabled` and `two_factor`
store TOTP state. Deleting an auth user cascades to its sessions, accounts,
two-factor records, and Hive identity, but occupied positions restrict deletion
of a referenced Hive identity until those positions are released.

## Read and merge flow

1. The frontend requests the cluster list and initially selects cluster number 1.
2. Layout and occupancy load independently for the selected cluster.
3. The API parses and validates the JSON layout on each config read.
4. The occupancy repository filters occupied positions by `cluster.name` and
   joins row, Hive identity, and auth user data.
5. The frontend matches entries by `(row, place)` number. Configured places absent
   from occupancy are free. Gaps remain non-interactive spacing.
6. The frontend derives summary counts and renders the map once both snapshots exist.

Occupancy for an unknown place does not create a new map cell. The separate
`config-validation` endpoint reports `ORPHANED_OCCUPANCY` errors, but the web map
does not call it yet. Duplicate occupancy keys collapse to the last entry in the
frontend map; there is no separate duplicate-warning UI.

## Updates and recovery

After a successful occupancy load, the frontend opens SSE. The server shares
one poller and snapshot per subscribed cluster within each API process. It emits
only changed/new occupied entries and freed coordinates, with no event history.
Successful HTTP occupancy reads also replace this shared baseline; it is not
tracked per subscriber. The frontend removes freed entries, then upserts occupied
entries. Multiple API processes have independent polling and snapshot state.

A `DB_UNAVAILABLE` event retains the existing map, marks occupancy stale, and
schedules a snapshot recovery attempt after 30 seconds. Failed recovery repeats;
a successful snapshot or delta clears stale state. A transport failure closes
the stream, checks the session, and retries via a fresh snapshot after 30 seconds.
An unauthorized/forbidden session stops reconnecting.

Snapshot `lastUpdated` is the API's successful-read time. On a delta, the frontend
uses its local receipt time. Unchanged server polls send no timestamp update;
keepalive comments do not prove occupancy freshness. There is no age-based stale
threshold, and transport failures alone do not immediately mark the map stale.

Switching clusters cancels prior requests/streams and hides the old cluster's
snapshot. A failed initial map load shows a retry action; a later failed snapshot
refresh preserves existing data.
