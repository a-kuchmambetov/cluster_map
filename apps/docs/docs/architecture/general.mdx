# General

In this section you can see general information about **Cluster Map architecture** like application diagram and folder structure.

## Architecture

<ThemeImage src="img/architecture/diagram-light.svg" darkSrc="img/architecture/diagram-dark.svg" alt="Architecture diagram" />

For domain **map-hive.pp.ua** we are using Cloudflare with proxy enabled. It gives us some default protection (server ip hidden, bots) as well as free SSL certificate, and comfartable way to manage domain name in general.

In the heart of application is Nginx which serving content and routing requests. For routing using next url paths:

- **/** - static Frontend generated from **React / Vite**
- **docs/** - documentation for developers based on **Docusaurus**
- **api/** - **Express** api server which comunicates with database via **Drizzle**

## Project folder structure

Structure based on monorepo with all "applications" based in apps folder and all additional resources, which can be shared between them, in packages. There are also some other files in root of the repo.

```text
  /
  ├── apps/
  │   ├── web/
  │   ├── api/
  │   └── docs/
  └── packages/
      ├── db/
      ├── validators/
      ├── errors/
      └── types/
```

### Root

In the root of the project are configs and deployment ralated files.

Pnpm related files:

- **pnpm-lock.yaml** Auto generated
- **pnpm-workspace.yaml** Contain settings for monorepo. See [pnpm docs](https://pnpm.io/pnpm-workspace_yaml)
- **package.json** Commands for development and deployment, and with couple packages for Prettier

Configs:

- **tsconfig.base.json** Base template for TS configuration used as "extend" for api and packages, to repeat code less between all configs
- **eslint.config.js** Config file for TS linting
- **.prettierrc** Config for prettier formation with C style formating (Semicolon at the end of the line and double quotes)
- **nginx.conf/s** Nginx file configuration for deployment and confs for per service deployment
- **Dockerfile/s** Same as for nginx confs. One centrilized and separate files for deployment
- **.env.example** Contains template of .env secrets for development/staging/production. While production values are stored in Github Secrets too

### Packages

Packages are modules which can/will be used for multiple applications.

Currently there are:

- **db/** Contains drizzle [configuration](https://orm.drizzle.team/docs/drizzle-config-file) and database [schemas](https://orm.drizzle.team/docs/sql-schema-declaration)
- **validators/** TS validation [schemas](https://zod.dev/basics) based on Zod
- **errors/** AppError class for errors managment
- **types/** Shared TS types

### Applications

For **docs** most important folder is **docs/docs**, it contains .mdx files with content for documentation. **src/** contains custom Docusaurus pages, components and styles. **static/** contains images and other public files. See [docusaurus CLI command](https://docusaurus.io/docs/installation#scaffold-project-website).

Api has next structure:

- **index.ts** Node.js Express server start only
- **app.ts** Express setup of cors and router linking
- **config/** Contains config related files like env variables
- **routes/** Contains api routes
- **middleware/** Contains Express middleware like error handler and request validation
- **features/** Contains feature related code
  - ***.routes.ts** Defines endpoints and attaches middlewares
  - ***.routes.test.ts**
  - ***.controller.ts** Functions that is used in routers, call services
  - ***.controller.test.ts**
  - ***.service.ts** Main business logic
  - ***.service.test.ts**
  - ***.repository.ts** All db related queries
  - ***.repository.test.ts** Only when using: filters, joins, pagination, sorting, transactions, duplicate checks, custom SQL, authorization-related query, constraints
  - ***.model.ts** Definitions for database structure (tables, relations, etc), in our case in **@repo/db drizzle schema**
  - ***.schema.ts** Schemas for data validation (a.k zod), in our case in **@repo/validators zod schemas**
  - ***.types.ts** TypeScript types that used in files above. Use **@repo/types** if shared between multiple apps
- **lib/** Contains shared api helper code

Web has next structure:

- **main.tsx** React application entry point
- **components/** Contains reusable UI components
- **pages/** Contains page components
- **providers/** Contains React providers like router and theme
- **hooks/** Contains reusable React hooks
- **styles/** Contains global styles, theme and typography
- **utils/** Contains helper functions and static data
- **types/** Contains frontend TS types
