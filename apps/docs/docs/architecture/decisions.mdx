# Architecture Decisions

This page separates choices encoded in current code from unresolved production
and product policies. Record future accepted decisions in linked ADRs.

## Implemented choices

### Authentication and access

Viewers register and sign in with email/password through Better Auth. New
accounts require administrator approval before session creation. The API checks
current approval for cluster requests and rechecks open SSE streams every
20 seconds. Health checks are public.

Approved administrators use `/admin/users`, `GET /api/auth/pending-users`, and
`POST /api/auth/confirm/:id` to approve accounts. `:id` is a single-use approval
token, not the user's ID. Hive OAuth and 2FA remain unimplemented.

### Layout and occupancy

JSON layout and database occupancy are separate responses. The frontend merges
by row/place number; config cluster IDs match database cluster names. A missing
occupancy entry means a configured place is free. Gaps never count as places.

### Refresh interval

SSE delivers deltas from a shared server poller. The poll interval is a fixed
30-second constant, with the next poll scheduled after the previous one finishes.
Frontend recovery/reconnect attempts also use 30 seconds. These are current code
constants, not environment settings or guaranteed maximum data age.

### Documentation hosting

Docusaurus is configured for `https://docs.map-hive.pp.ua/`. Compose serves docs
separately on port 8081 by default; production DNS/TLS setup is external.

## Open decisions

### Displayed peer identity

The implemented map response exposes nullable `intraName`, `displayName`, and
`photo`. Confirm the production audience and retention policy for these fields.
Auth session and administrator approval responses also contain account email;
map privacy constraints must be distinguished from account management.

### Stale-data threshold

The UI marks stale data after failed snapshot refreshes or database SSE errors.
There is no age threshold or successful-unchanged-poll freshness event. Define
acceptable data age and how transport loss should affect the indicator.

### Configuration-warning audience

The API returns mismatch details to approved viewers, but the frontend does not
request or display them yet. Decide how to expose actionable warnings to viewers
and operators.

### Production database access

Occupancy reads and auth writes currently share one DB client/credential.
Define production source integration, separate privileges where needed, migration
ownership, and backup/restore procedures. A read-only role for the whole app
cannot support registration, sessions, and approvals.

### Performance targets

Define measurable page-load, interaction, API-response, supported-map-size, and
accessibility acceptance criteria. Test browser compatibility before claiming it.
