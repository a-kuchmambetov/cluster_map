# Architecture Decisions

This page separates choices encoded in current code from unresolved production
and product policies. Record future accepted decisions in linked ADRs.

## Implemented choices

### Authentication and access

Viewers sign in with GitHub through Better Auth. New accounts require administrator
approval before session creation. Email/password sign-in and TOTP two-factor
authentication have been removed. The API checks
current approval for cluster requests and rechecks open SSE streams every
20 seconds. Health checks are public.

Each protected request resolves a fresh server-side session, bypasses cookie
cache, and reads current approval and privileges. Authentication supplies an
optional typed `res.locals.actor`; checked authenticated handlers expose it as
required only after authentication. `requireRole("admin")` authorizes admin
routes without another session lookup. Business services have no HTTP-header
dependency; auth transport and periodic SSE revalidation still resolve sessions.
`/api/auth/session` reuses the resolved sanitized public session.

Approved administrators use the `/admin/users` web screen and the separate
admin feature: `GET /api/admin/users` (optionally `?status=pending`),
`POST /api/admin/users/:id/approve`, and `DELETE /api/admin/users/:id`.
Approval atomically changes `approved=false` to true by opaque user ID; replay
returns 404. Self-deletion is forbidden. No approval tokens are generated,
stored, or exposed. Legacy auth administration routes are removed without
aliases. The approval limiter is attached explicitly to its POST route.
Hive OAuth remains unimplemented.

### Layout and occupancy

JSON layout and database occupancy are separate responses. The frontend merges
by row/place number; config cluster IDs match database cluster names. A missing
occupancy entry means a configured place is free. Gaps never count as places.

### Refresh interval

SSE delivers deltas from a shared server poller. The poll interval is a fixed
30-second constant, with the next poll scheduled after the previous one finishes.
The frontend waits 30 seconds before reopening a lost SSE connection; after a
`DB_UNAVAILABLE` event it keeps the stream open and waits for the server's
recovery snapshot. These are current code
constants, not environment settings or guaranteed maximum data age.

### Documentation hosting

Docusaurus is configured for `https://docs.map-hive.pp.ua/`. Development Compose
runs Docusaurus on port 3000; production uses the static docs image, which serves
files on port 80, with DNS/TLS configured externally.

## Open decisions

### Displayed peer identity

The implemented map response exposes nullable `intraName`, `displayName`, and
`photo`. Confirm the production audience and retention policy for these fields.
Auth session and administrator user-list responses also contain account email;
map privacy constraints must be distinguished from account management.

### Stale-data threshold

The UI marks stale data after failed snapshot refreshes, database SSE errors, or
SSE transport loss. There is no age threshold or successful-unchanged-poll
freshness event. Define acceptable data age.

### Configuration-warning audience

The API returns mismatch details to approved viewers, but the frontend does not
request or display them yet. Decide how to expose actionable warnings to viewers
and operators.

### Production database access

Occupancy reads and auth writes currently share one DB client/credential.
Define production source integration, separate privileges where needed, migration
ownership, and backup/restore procedures. A read-only role for the whole app
cannot support registration, sessions, and approvals.

### Performance targets

Define measurable page-load, interaction, API-response, supported-map-size, and
accessibility acceptance criteria. Test browser compatibility before claiming it.
