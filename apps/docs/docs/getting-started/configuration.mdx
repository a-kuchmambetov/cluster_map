# Configuration

Runtime settings come from environment variables; physical layout comes from
`apps/api/src/config/clusters.json`. See [Map Configuration](../reference/map-configuration).

## Root environment file

The API and database configuration load `../../.env` relative to their workspace
working directories. Vite also uses the repository root as `envDir`.

```bash
cp .env.example .env
```

A consistent local example is:

```dotenv
API_PORT=5000
WEB_ORIGIN=http://localhost:5173
VITE_API_URL=
PG_USER=app
PG_DB=app
PG_PASSWORD=app
PG_HOST=localhost
PG_PORT=5432
BETTER_AUTH_SECRET=replace-with-a-random-secret-at-least-32-characters
BETTER_AUTH_URL=http://localhost:5000
```

Generate the auth secret with `openssl rand -base64 32`. The template currently
sets API port 5001 but auth URL port 5000; choose one port and align both.
Do not commit the resulting `.env`.

## API and database configuration

The API validates `API_PORT` as a number and applies defaults for `WEB_ORIGIN`
and `PG_*`. The DB client constructs a PostgreSQL URL from `PG_USER`,
`PG_PASSWORD`, `PG_HOST`, `PG_PORT`, and `PG_DB`, defaulting to
`app`, `app`, `localhost`, `5432`, and `app` respectively. User/password are
URL-encoded. Neither module currently reads `PG_PASSWORD_FILE` or a supplied
`DATABASE_URL` environment variable.

Auth configuration is initialized lazily when auth functionality is used.
`BETTER_AUTH_SECRET` must have at least 32 characters and `BETTER_AUTH_URL` must
be a URL. A healthy `/api/health` response does not validate auth configuration
or prove that migrations have run.

Use `pnpm db:up`, `pnpm db:migrate`, and optionally `pnpm db:seed` for local setup.
The DB client is shared by map reads and auth writes.

## CORS and environment mode

Credentialed CORS allows exactly `WEB_ORIGIN` in every mode. Development wraps
that same origin in an array; it does not add another origin. Auth POST requests
also reject explicit untrusted browser origins and cross-site requests without
an Origin header.

`NODE_ENV=production` masks internal errors and enables JSON request logs.
Other modes expose more diagnostic error information. See the
[API error envelope](../reference/api#error-envelope).

## Frontend configuration

`VITE_API_URL` is an optional API origin without `/api` for local Vite development.
An empty value makes requests use same-origin `/api`, which Vite proxies to
`http://localhost:API_PORT` (default 5001). The Web container requires `API_URL`
at startup, such as `https://api.example.com`; it serves that origin through
`/config.js`, and browser requests go directly to `${API_URL}/api`. Browser HTTP
requests and EventSource connections include credentials. Set API `WEB_ORIGIN` to
the public Web origin and `BETTER_AUTH_URL` to the public API origin.

## Container configuration

Compose sets API auth URL and allowed origin from `DOCKER_WEB_ORIGIN`
(default `http://localhost:8080`). If changing `WEB_PORT`, update that origin too.
See [Environment Variables](../reference/environment-variables) for the full list.
