# Local Development

The repository includes the cluster map, authentication, administrator approvals,
PostgreSQL schemas, tests, and a full-stack Compose setup.

## Prerequisites

- Node.js 24 is used by the API and web Dockerfiles and is a suitable local baseline.
- pnpm 11.5.2, matching the root package-manager configuration.
- Docker Compose for the local database, or an existing development PostgreSQL server.

## Install and configure

Run from the repository root:

```bash
pnpm install
cp .env.example .env
openssl rand -base64 32
```

Put the generated value in `BETTER_AUTH_SECRET`. For this walkthrough, set
`API_PORT=5000` and `BETTER_AUTH_URL=http://localhost:5000`. The checked-in template
currently uses `API_PORT=5001` but an auth URL on port 5000; align those values
before starting. Keep `WEB_ORIGIN=http://localhost:5173` and `VITE_API_URL=` for
the local Vite proxy. See [Configuration](./configuration).

## Prepare the database

```bash
pnpm db:up
```

Wait for the DB to become healthy (`docker compose ps db`), then run:

```bash
pnpm db:migrate
pnpm build
pnpm db:seed
```

Migrations create auth and Hive tables. `pnpm build` builds all workspaces except
docs and makes shared `dist/` packages available. The optional seed writes demo
accounts and occupancy to the configured database; use a local/demo database.
It refuses to run with `NODE_ENV=production` and is not a live simulation agent.

On a fresh seed, sign in with `demo-admin@example.test` or
`demo-member-1@example.test` and password `Demo-password-123!`. The administrator
can approve `demo-pending@example.test` from `/admin/users`. Existing demo accounts
retain their passwords and approval/role state when seeding again.

## Start web and API

```bash
pnpm dev
```

| Service | URL with the walkthrough configuration | Behavior                                                 |
| ------- | -------------------------------------- | -------------------------------------------------------- |
| Web     | `http://localhost:5173`                | Login, registration, protected map, and admin approvals. |
| API     | `http://localhost:5000`                | Health, auth, cluster HTTP endpoints, and SSE.           |

Vite proxies `/api` to `localhost:API_PORT`. If Vite chooses another port, update
`WEB_ORIGIN` and restart the API.

```bash
curl http://localhost:5000/api/health
```

A reachable database returns `200` with `{ "status": "ok", "db": "ok" }`.
An unavailable database returns `503` with
`{ "status": "degraded", "db": "unreachable" }`.

## Start individual workspaces

```bash
pnpm --filter @repo/api dev
pnpm --filter @repo/web dev
pnpm start:docs
```

Docusaurus starts separately at `http://localhost:3000`; `pnpm dev` does not start
it. Use the API workspace command so relative `.env` and layout paths resolve.

## Common checks

```bash
pnpm typecheck
pnpm lint
pnpm fmt:check
pnpm --filter @repo/api test
pnpm --filter @repo/api test:integration
pnpm --filter @repo/web test
pnpm build:docs
```

See [Testing and Simulation](../development-and-testing/testing-and-simulation)
for the optional DB-backed test and [Deployment](../operations/deployment) for
running web, API, DB, and docs in containers.

`pnpm db:down` runs `docker compose down`, stopping the whole Compose project
without removing its named database volume. `pnpm start` runs workspace start
scripts, including built API, Vite preview, and the Docusaurus development server.
