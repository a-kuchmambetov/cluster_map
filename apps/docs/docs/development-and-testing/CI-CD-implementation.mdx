# CI/CD implementation

The implemented release pipeline uses three workflows:

- `ci.yml`: GitHub-hosted checks with disposable PostgreSQL 17, Node.js 24 and pnpm 11.5.2.
- `publish.yml`: runs required checks, then builds all three images on trusted
  self-hosted runners and publishes commit tags and digest artifacts to GHCR.
- `deploy.yml`: validates publication provenance, promotes existing digests,
  updates Coolify image configuration, polls deployments and checks public health.

Staging and production require GitHub Environment reviewer gates because the
initial migration mechanism is a controlled manual one-off container. Production
requires a successful staging deployment of the same main-branch publication.
Runtime Infisical credentials never enter CI or Docker builds.

See [Deployment](../operations/deployment) and the
[manual runbook](https://github.com/a-kuchmambetov/cluster_map/blob/main/manual.md)
for setup, migration approval, manual acceptance checks, credential rotation,
backup and rollback instructions. Infrastructure is provisioned separately;
checked-in automation alone is not evidence of a live deployment.
