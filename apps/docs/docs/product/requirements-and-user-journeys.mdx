# Requirements and User Journeys

This page describes the intended Cluster Map experience. Unless a requirement is
explicitly marked as implemented, it is a product target rather than a description
of the current application.

## Purpose and scope

Cluster Map helps a viewer find an available place in a physical cluster and
understand which places are already occupied.

The first usable release is expected to let a viewer:

- select a cluster;
- view its rows and numbered places;
- distinguish free places, occupied places, and layout gaps;
- see the total number of free places;
- inspect an approved subset of information about the peer at an occupied place;
- see when occupancy information was last updated;
- keep using the last successful map when a refresh fails.

The following are out of scope for the first release:

- booking or reserving a place;
- changing occupancy through Cluster Map;
- user and role administration;
- an administrative interface.

Authentication is an **open decision**. Earlier requirements assumed both
anonymous access and Hive authentication; neither is authoritative until the
access model is decided. Read-only behavior is required in either case. See
[Architecture Decisions](../architecture/decisions#authentication-and-access).

## Actors

### Map viewer

A map viewer wants to find a free place from a desktop or mobile browser. The
viewer needs current information, quick cluster navigation, clear place states,
and interactions that work without relying on hover or color alone.

### Displayed peer

A displayed peer is associated with an occupied place. They might not be actively
using Cluster Map, but approved identifying information about them can be visible
to viewers. The exact identity fields and access audience remain open decisions;
see [Privacy and Quality Requirements](./privacy-and-quality-requirements).

## Core user journeys

### Find a free place

1. The viewer opens Cluster Map.
2. The application loads the available clusters and selects a valid default when
   the viewer has not chosen one.
3. The viewer selects a cluster.
4. The application displays its rows, numbered places, and layout gaps.
5. The application displays the number of free places.
6. The viewer identifies a free place from its label and status indicator.

The result must identify the cluster, row, and place number unambiguously.
Possible alternative results: a missing cluster, no free places, invalid layout
configuration, unavailable occupancy data, and previously loaded data becoming
stale.

### Inspect an occupied place

1. The viewer focuses, clicks, taps, or hovers over an occupied place.
2. The application displays only the approved peer and place information.
3. The viewer dismisses the details or moves to another place.

Hover must not be the only way to open the details. Keyboard and touch users must
receive equivalent information.

### Receive occupancy updates

1. The application records the time of a successful map load.
2. It requests new occupancy data at a configurable interval.
3. The existing map stays visible and interactive while the request is running.
4. After success, the map and last-updated time change together.

Polling is the proposed first implementation. Thirty seconds **(30 sec)** is a candidate
interval, not an accepted requirement.

### Continue after a refresh failure

If a refresh fails after at least one successful load, the application must keep
the previous map visible, mark it as potentially stale, show a non-blocking error,
and retry later. If no map has loaded successfully, it must show a full error state
with a retry action.

### Encounter a configuration mismatch

If occupancy data references a place missing from the layout configuration, the
application should keep valid parts of the map visible and report the mismatch.
Whether that warning is visible to all viewers or only through operational
monitoring is still undecided.

## User-visible states

| State                  | Expected presentation                                                               |
| ---------------------- | ----------------------------------------------------------------------------------- |
| Loading                | A loading indicator that preserves the page structure.                              |
| Free                   | A labelled, accessible available place.                                             |
| Occupied               | A labelled, accessible place with optional peer details.                            |
| Layout gap             | Blank layout space with no number or interaction.                                   |
| No free places         | The map remains visible with a clear availability message.                          |
| Refreshing             | The existing map remains usable while new data loads.                               |
| Stale                  | The previous map remains visible with its last-updated time and a warning.          |
| Configuration mismatch | Valid map content remains visible with an appropriate warning or operational alert. |
| Initial load failure   | An error message and retry action.                                                  |
| Cluster not found      | A clear message and a way to choose another cluster.                                |

The underlying concepts and proposed merge behavior are defined in
[Domain Model and Data Flow](../architecture/domain-model-and-data-flow).
